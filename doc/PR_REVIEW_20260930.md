## PR #11 repair

The test-only draft exposed a genuine NASM3 incompatibility. With ORG 256,
`target: nop` followed by `mov ax,[bx-target]` emits `90 8B 07` in native
NASM 3.02, while the historical pynasm profile emits `90 8B 87 00 FF`.
NASM's parser marks a negative current-section base as self-relative. Its
memory encoder chooses a zero/byte displacement using the section offset;
word and direct-address operands still use the relocated absolute value.
References at the exact 3.02 source commit:
[parse_mref](https://github.com/netwide-assembler/nasm/blob/4a56d66ed9626d5a3ded5414c9d8b7f1a48ce065/asm/parser.c),
[memory encoding](https://github.com/netwide-assembler/nasm/blob/4a56d66ed9626d5a3ded5414c9d8b7f1a48ce065/asm/assemble.c).

The repair retains affine section provenance in address expressions and keeps
displacement selection separate from word relocation, only in nasm3 mode.
It rejects negative bases from another section and preserves the historical
profile. It does not treat the compatibility quirk as the desired mathematical
address or as evidence about execution on hardware.
